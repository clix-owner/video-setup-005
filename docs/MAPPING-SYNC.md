# Deleted Streamtape video mapping sync
Upload .github/workflows/clixarena-mapping-sync.yml and scripts/clixarena_mapping_sync.py along with the existing scripts to your Actions repository default branch. No Vercel redeploy is required for this change.
Uses the existing STREAMTAPE_LOGIN, STREAMTAPE_KEY and MAPPING_PASSWORD Actions secrets, plus automatic github.token with contents write. No new secrets.
The schedule runs hourly at minute 17 (GitHub schedules may be delayed); manual Actions dispatch is also available. It does not launch an encode or upload, and is not matched by the successful VIDEO run cleanup workflow.
Each batch contains up to 100 IDs. Only an explicit individual result status 404, confirmed twice five seconds apart, allows removal. Missing entries, 403, 451, 429, 5xx, transport errors or malformed responses do not count as deletion. Global service/authentication errors stop the sync. When the server returns unknown instead of 404 a deleted file is deliberately preserved until a future definite result.
Encrypted mappings stay encrypted. A SHA-bound atomic Contents API commit prevents overwriting a concurrent mapping upload; on conflict it rereads and rechecks the latest mappings. All rows referencing a confirmed missing file ID are removed, including their attached subtitle metadata, but subtitle files and actual Streamtape files are not deleted. No IDs, URLs, credentials or plaintext mapping backups are logged or published. Git history remains available for recovery.
Tests: explicit per-ID status classification; repeated confirmation; preservation of replacement uploads and unrelated fields; API exception propagation. No real sync was triggered.
