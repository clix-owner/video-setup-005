# URL recovery update — 2026-10-15
Update both github-actions/ and vercel-ui/, commit/push and redeploy Vercel. Start a new request; rerunning a pinned old request uses its old code.
HTTP 401/403/404/410 during video download pauses a portal job for up to 20 minutes. These statuses can mean expiry OR access denial; a new URL is not guaranteed to fix blocked hosts. In Track a requested run, supply a fresh HTTPS link and press Resume download. The SAME runner restarts the download from zero, not the previous byte offset. Maximum three replacement attempts. Manual jobs without a portal job ID fail with a clear message.
Replacement URLs are encrypted using the existing MAPPING_PASSWORD, which must match between Vercel and Actions. No new secrets. URLs are not returned by status or printed. Encrypted state can remain in repository history.
Output MP4 codec and duration validation failures now give safe explicit reasons. The two-second duration check is preserved; the provided log alone does not identify the original root cause. Damaged/truncated files are not uploaded.
Cleanup job already has a success-only event guard and rechecks the target status immediately before deleting. Failed/cancelled runs are never deleted. GitHub workflow_run emits an entry on every completion, so failed runs may produce a SKIPPED cleanup workflow entry; no cleanup runner or steps execute for those events.
Validated: portal 61 regression tests plus new encrypted replacement API test; seven torrent tests; Python syntax and portal JavaScript syntax. No live run, upload or deployment triggered.
